Overview

Leaf-node shapes auto-grow to enclose their bound label, and labels auto-wrap to a per-shape target aspect ratio. The SVG renderer emits one <tspan> per wrapped line, vertically centered as a block. The feature exists because labels are increasingly agent-authored — a bulk-triage diagram with prose like "Promote (FB only — cluster unmatched → new tickets)" used to overflow its default 160×60 box, and "tell the user to insert \n" wasn't a real solution.

How it fits the pipeline

All text decisions happen before ELK runs — ELK has no font metrics and can't break lines. The desugar layer sizes nodes and label boxes from the wrapped block; the SVG renderer re-derives the same lines on the way out. Both layers call the same pure helper with the same inputs, so they agree by construction.

Concretely: nodes ship to ELK with width and height computed from the wrapped block (was: defaults 160×60). Labels ship with width = max line width (was: total text length). The renderer reads the laid-out node width and calls the same helper with the same aspect to reproduce the breaks.

Choosing where lines break

A wrapped block is a rectangle of L lines, each with line height lh = fontSize × 1.25. To target aspect R = width/height for a label of total glyph width W, model L ≈ W/t at target width t. Then R = t / (L · lh) = t² / (W · lh), so: 

t = √(R · W · lh)

The chosen aspect comes from a per-shape table. Squarer aspects counteract larger shape-inflation factors (see Growing the shape) so the visual ribbon stays similar across shapes.

ShapeAspect RWhy
rectangle2.0Wide ribbon — defaults for prose-shaped labels.
ellipse1.6Closer to circle to counteract √2 inflation.
diamond1.5Squarer because diamond corners eat both axes.

Greedy word-wrap fills lines against that target: each word lands on the current line if it fits, otherwise it starts a new one. Long single words overflow rather than break mid-word. Explicit \n always wins — paragraphs author-supplied with a hard break are never re-broken, and the wrap target is floored at the widest such paragraph so author intent is preserved.

At render time the same call produces the same lines array, which the SVG renderer emits as one <tspan x="cx"> per line under a single <text> anchor — the parent's y is shifted up by (N−1) · lh / 2 so the block centers on the shape. Single-line labels emit no <tspan>.

Realised aspect drifts from the target — greedy fill rounds up at word boundaries, and the explicit-paragraph floor widens multi-paragraph blocks. Drift bounds and measurements live in plans/text-fitting.html.

Growing the shape

The wrapped block must fit the shape's inscribed rectangle, not its bounding box. Inflating the block's (w, h) by a shape-specific factor before adding padding gives the bbox to hand to ELK.

ShapeInflationWhy
rectangle1.0Text block is the inscribed rect.
ellipse√2Max inscribed rect of an ellipse is bbox/√2.
diamond2.0Max inscribed rect of a square rotated 45° is bbox/2.

Each side gets NODE_TEXT_PADDING = 12 px of inner breathing room. The final dimensions are floored at the historical defaults (160×60) so labelless or tiny-label nodes keep their existing minimum footprint — single-word labels don't shrink to a hugging box.

Author controls

Three knobs cover the cases auto-sizing gets wrong:

KnobEffect
width / height on a node User-supplied dimensions win outright; auto-sizing is skipped for that node. ELK sees the supplied values; the renderer wraps to (width − 2·pad) / inflation.
\n inside a label Forces a hard break. Multi-paragraph labels never re-break — author intent wins over the closed-form target.
style.size on a label Per-label font size; the wrap and inflation calculations adapt to the chosen size (line height scales with it).

Edge labels are split-only: explicit \n is honored, but they do not auto-wrap — short ribbons like "FB: creates" read worse split than as a single line. EDGE_LABEL_ASPECT = 3.0 is exported from src/text/wrap.ts for callers that may want it later; no current caller uses it.

Limits

  • No real font metrics — char width is a flat fontSize × 0.55 multiplier (Tahoma/Verdana ratio, slight overcount on the safe side). CJK and emoji silently undercount.
  • No in-word breaking — words longer than the target overflow rather than split.
  • No per-line ellipse tapering — uses √2 bbox inflation, not curve-following text.
  • No iterative aspect refinement — one closed-form pass; realised aspect drifts within ~±50% of target.
  • Only the bound (inside-center) label sizes the node. Outside labels do not push the shape larger.
  • Container nodes keep their existing top-band sizing; auto-sizing applies only to leaf nodes.
