State machine

Good for: documenting an entity's lifecycle as discrete states with the events and loops that move it between them. Color specific states with classDef (note: fixed-hex fills don't auto-adapt to light/dark).

Mermaid source 
stateDiagram-v2
  [*] --> Pending: start
  Pending --> Running: dequeue
  Running --> Success: ok
  Running --> Failed: error
  Failed --> Retry
  Retry --> Pending: requeue
  Success --> [*]
  classDef good fill:#d4edda,stroke:#28a745,color:#155724
  classDef bad fill:#f8d7da,stroke:#dc3545,color:#721c24
  class Success good
  class Failed bad

Class / UML

Good for: specifying object-oriented structure — classes, their fields and methods, and inheritance or association relationships.

Mermaid source 
classDiagram
  class Animal {
    +String name
    +move() void
  }
  class Dog {
    +String breed
    +bark() void
  }
  class Car {
    +String model
    +start() void
  }
  class Engine {
    +int horsepower
  }
  class Logger {
    +log(String msg) void
  }
  Animal <|-- Dog : extends
  Car *-- Engine : composes
  Team o-- Player : has
  Service ..> Logger : uses
  Mediator <--> Worker : talks

Gantt

Good for: laying out a schedule of tasks with their durations, dependencies, and milestones.

Mermaid source 
gantt
  title Release plan
  dateFormat YYYY-MM-DD
  section Build
  Spike       :a1, 2026-06-01, 3d
  Implement   :a2, after a1, 5d
  section Ship
  Review      :a3, after a2, 2d
  Release     :milestone, after a3, 0d
