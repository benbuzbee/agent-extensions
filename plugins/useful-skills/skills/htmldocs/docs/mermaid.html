What it is

Author a diagram by writing Mermaid DSL inside a <pre class="mermaid">, plus one pinned-CDN <script> per document. Open the file anywhere with network — file://, a browser, an HTML preview — and Mermaid renders every block into an inline <svg> on open. No server, no build step, no separate render pass. The DSL stays in the file as the canonical, diffable, agent-fluent source; the SVG is ephemeral.

It's the step up from hand-rolled inline <svg> — fine for three boxes, painful past that. Agents are already fluent in Mermaid, so a sequence, state, or flow diagram drops in cheaply with no tool call.

How it works

Two pieces in the file. A <figure data-kind="diagram"> wrapping a <pre class="mermaid"> per diagram (the figure is the addressable unit — it gets an id only when it's a link or comment target), and one Mermaid script per document near </body>. On open, mermaid.run() finds every pre.mermaid on the page and replaces it with SVG, so one script covers all diagrams.

The figure with its DSL, and the proven one-time script copied into each diagram doc:

<!-- one per diagram -->
<figure data-kind="diagram">
  <pre class="mermaid">flowchart LR
  A[Source] --> B[Sink]</pre>
</figure>

<!-- one per document, near </body> -->
<script type="module">
  import mermaid from 'https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs';
  const dark = matchMedia('(prefers-color-scheme: dark)').matches;
  mermaid.initialize({ startOnLoad: false, theme: dark ? 'dark' : 'default' });
  await mermaid.run();
</script>

Two htmldocs-specific rules (the Mermaid syntax itself the model already knows): escape <, >, & as &lt; &gt; &amp; inside the <pre> — the browser decodes them before Mermaid parses, so a sequence arrow is written W-&gt;&gt;DB and a class inheritance arrow Animal &lt;|-- Dog — and one script per document, not per figure. The full contract (figure shape, diagram-type routing, gotchas) lives in references/mermaid.md; worked examples per genre are in the gallery.
