Overview

User asks the agent to open a doc in review mode. The agent runs serve.sh in the background and hands User a localhost URL. User opens it, selects any text inside an <article>, clicks the Comment button that appears, and writes a note. The note lands in a JSON sidecar under the server's sidecar directory (auto-tmp by default, or pinned via --sidecar-dir). On its next pass the agent reads that file and addresses each comment via HTML edits.

Components

serve.sh

The agent's entry into review mode. A small Bash shim next to SKILL.md that preflights node on PATH, picks a free port in 8000–8099, prints the URL: line, and execs the Node server (dist/serve.mjs) bound to 127.0.0.1. Accepts a file or a directory; either way every .html under the served folder becomes reviewable. Optional --sidecar-dir <path> pins the sidecar location for resume; absent it, the server picks an auto-tmp directory and announces it via the second stdout line (SIDECAR_DIR:). Invocation contract — argument shapes, the two-line stdout, what to hand User — in references/comments.md.

The widget (dist/comments.mjs)

A single ESM artifact (~130 KB, checked in) bundled by esbuild from TypeScript sources under src/comments/. The server injects it at runtime — pages on disk stay vanilla, with no <script> wiring required. The widget mounts only when the inline JSON seed (#__htmldocs_comments) is present in the DOM; absent seed means review mode isn't active and the page renders normally.

Modules:

  • main.ts — CommentsWidget class; bootstrap and init flow.
  • anchor.ts — encode/decode between a DOM Range and the W3C TextQuoteSelector triple (32-char prefix/suffix windows, Hypothesis convention). The encoder also records the ids of every <article> the selection intersects in an anchor.sections array — pure metadata, the decoder always searches the full document and uses prefix/suffix as the disambiguator. The popover gate (ui.ts) requires the selection to intersect at least one <article>; selections spanning multiple articles are supported, selections outside every article are not.
  • persistence.ts — HttpSidecarStore; reads the inline JSON seed on construction, writes via PUT /__htmldocs/sidecar/<doc-path> where the path is derived from location.pathname.
  • ui.ts — selection popover, <dialog> composer, margin-gutter thread bubbles.
  • types.ts — Anchor, Comment, CommentsModel, TestHandle; the same CommentsModel the server validates against.

Styles inject via a constructable CSSStyleSheet on document.adoptedStyleSheets with the --htmldocs-cmt-* prefix so they cannot collide with the host doc's tokens. Highlights register as Range objects under one named registry (htmldocs-cmt) in CSS.highlights — no <mark> wrappers, no DOM rewriting.

HTTP endpoint (PUT /__htmldocs/sidecar/<doc-path>)

The persistence transport between widget and disk. One write route; body is the full CommentsModel JSON. The doc path in the URL is validated the same way a static GET is — it must resolve under --root to an .html / .htm file — and the resulting sidecar lands under SIDECAR_DIR, mirroring the doc's root-relative path. Writes are atomic, so a crash mid-write cannot truncate the sidecar. Concurrency semantics (two tabs against the same doc) are last-writer-wins — see § Known friction.

Sidecar JSON

The durable artifact between widget and agent. One JSON file per doc, under SIDECAR_DIR, mirroring the doc's root-relative path (overview.html → <SIDECAR_DIR>/overview.comments.json; sub/bar.html → <SIDECAR_DIR>/sub/bar.comments.json). Multi-doc sessions produce one sidecar per doc that received a save; they never aggregate. Schema (schema: 1) is canonical in references/comments.md; v1 comments are implicitly open (no resolve/thread/orphan-flag fields).

Agent recipe

Entry point lives in SKILL.md § Review mode: run bash <htmldocs-skill>/serve.sh path/to/doc.html in the background, capture the URL: line, hand it to User. To read comments back, Read the sidecar JSON directly. Full recipe — sidecar shape, orphan handling — in references/comments.md.

Data flow

  1. Inject. The server reads the current sidecar from disk and rewrites the HTML response, inserting the bundle <script> and an inline <script type="application/json" id="__htmldocs_comments"> carrying the sidecar contents. The browser loads the doc; the widget sees the seed, mounts, adopts its stylesheet, and registers existing anchors as CSS.highlights entries — zero network round trips for initial state.
  2. Capture. User selects text inside an <article>. The selection popover surfaces a Comment button. Clicking it calls encodeAnchor(range) immediately — freezing prefix/exact/suffix against the live DOM — then opens a <dialog> composer with the textarea focused.
  3. Save. Submit appends the new comment, serializes the model, and PUTs it to the sidecar route for this doc. The server lands the sidecar atomically under SIDECAR_DIR. The widget updates its highlights and gutter without reloading. Write errors roll the in-memory model back.
  4. Read-back. On the next agent turn the agent reads each sidecar under $SIDECAR_DIR directly (find "$SIDECAR_DIR" -name '*.comments.json' lists every doc that received a save) and addresses each comment via HTML edits. Reloading any page re-seeds from disk, so User sees whatever the agent last left there. v1 agents do not write the sidecar; User clears entries by editing the JSON.

Known friction

  • Two-tab last-writer-wins. Opening the same review URL in two tabs and submitting from each leaves only the second body on disk — the PUTs collapse to the most recent write. The losing tab learns on next reload, when the inline seed re-reads the on-disk sidecar. Documented, not solved; conflict resolution (ETags, version field, server-side merge) would dominate the rewrite. See plans/review_server_buildout.html § Decisions.
  • Port collisions outside 8000–8099. serve.sh probes that range and exits if every port is taken. User running 100+ dev servers (or a stale serve.sh per port) needs to free one before review mode will start.
